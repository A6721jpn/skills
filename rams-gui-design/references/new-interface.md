# Establishing a new interface

Use this guidance when the task needs a new interaction model or composition.
Treat it as a set of design decisions, not a sequence or a required document.

## Find the organizing relationship

Identify what the user acts on and what makes the next decision possible. The
organizing relationship might be input and result, comparable records, change over
time, or a selected object and its properties. Make that relationship visible in
the layout. Navigation and summaries earn space by supporting the work.

For example, a precision tool benefits from seeing a changed value beside its
effect; a comparison tool benefits from aligned values on a common scale. The
same visual theme can conceal this difference. Choose the interaction structure
that reduces the user's interpretation before tuning its appearance.

## Give the product its own grammar

Derive density from frequency of use, information relationships, and input mode.
Use open framing around compact related controls when it clarifies their
relationship. Preserve comparison and object context as available space changes.

Give typography, spacing, surface boundaries, and signals consistent roles.
Choose sizes and spacing from the actual content and platform, using the skill's
selected typeface and color set. Color can identify operations, categories, or exceptions;
its allocation should explain importance. Softer geometry can still be restrained
when the roles remain clear. Physical cues are useful when they clarify affordance
or control mapping.

Use imagery, animation, or depth when they carry relevant information or explain
a transition. An effect that competes with the working object spends attention
without helping the task. Keep a recognizable, coherent identity in the details
that remain visible throughout use.

## Settle the important tradeoffs

Choose a working design rather than presenting routine choices for approval.
Consider alternatives where competing needs would materially change the result:
precision versus speed, persistent context versus space, or information density
versus ease of entry. Resolve them against the user's actual task. The number of
alternatives and documentation should follow the decision's importance.

Reduction can mean changing the interaction rather than deleting decoration.
An inline edit might remove a trip through a dialog; a persistent value might
remove the need to remember a previous screen. Keep labels, units, constraints,
and recovery where they prevent ambiguity. Show system truth, including freshness,
uncertainty, or commit state when it matters to the decision.
