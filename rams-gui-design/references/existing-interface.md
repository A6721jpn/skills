# Refining and reviewing an existing interface

Use the product's current interaction model, components, visual grammar, and
user familiarity as evidence for the design. Identify which relationship or
decision the requested change should improve.

## Change the source of the burden

If the request concerns appearance, improve hierarchy and coherence at that
scope. When it concerns usability, examine whether the difficulty comes from
structure, interaction, missing state, or visual emphasis. A control's styling
cannot repair an unclear relationship between its input and result.

Existing conventions provide continuity. When one materially obstructs the
requested outcome, change the affected convention coherently within the authorized
scope. Preserve familiar behavior where it helps the user's work. Use
[new-interface.md](new-interface.md) when a new composition is warranted.

## Review through the user's task

Tie each finding to an observed screen or state and a concrete consequence:
misreading a value, losing the current object, repeating an action, or being unable
to recover. Separate observed failures from plausible risks and evidence gaps.
Prioritize by effect on the job rather than conformity to a palette or component
catalog. Recommend the smallest correction that addresses the cause.

When reviewing reduction, consider cognitive and operational effort alongside
element count. Removing a visible unit, state, or contextual label may create
more work elsewhere. Explain a retained or changed element through its function
when that decision matters to the review. Numeric scoring belongs to a requested
evaluation with explicit criteria and evidence.
